# AI 洞察配方指南：从全球新闻中最大化挖价值

本文档面向 FeedGen 阅读器中的 **洞察配方（InsightRecipe）** 能力：对「当前文章列表」跑一次可编辑提示词模板，用不同透镜从同一批标题/摘要中挖掘不同价值。

相关实现：

- 数据表：`user_insight_recipes`
- API：`/api/ai/recipes`、`/api/ai/recipes/:id/run`
- 前端：阅读器工具栏 **AI** 菜单 → 配方列表 /「管理配方」
- 内置默认：`backend/src/services/ai/insightRecipeDefaults.ts`（简报总结、风险挖掘）

---

## 1. 产品定位：配方不是 Skill

| 概念 | 本应用含义 |
|---|---|
| 洞察配方 | 对当前可见文章列表执行一次提示词模板 |
| 上下文 | 默认标题；可选摘要、来源（`context_fields`） |
| 不包含 | Agent 多步工具调用、联网搜索、全文长文精读、跨用户配方市场 |

**一句话**：同一批新闻标题 + 不同配方 = 不同成果。价值来自「透镜正交」，不是再写一条更长的总结。

### 1.1 运行时占位符

用户模板中可自由使用：

| 占位符 | 含义 |
|---|---|
| `{{scope_label}}` | 当前范围（Feed / 主题 / 今天…） |
| `{{title_count}}` | 条数 |
| `{{titles_block}}` | 按 `context_fields` 拼装的编号列表 |
| `{{today}}` | 当前日期 |

### 1.2 上下文字段建议

| 字段 | 适用场景 | 成本/噪声 |
|---|---|---|
| `title`（默认必选） | 几乎所有配方 | 低 |
| `summary` | 行业深挖、核实、对照、因果草图 | 中（信息更丰，也可能带进摘要噪声） |
| `source` | 多源对照、叙事分裂、议程设置、地区视角 | 低～中 |

原则：**一条配方只开它真正需要的字段**；简报类通常只需 `title`。

## 2. 设计原则：如何最大化挖价值

### 2.1 正交三透镜（每天至少各跑一类）

1. **发生了什么**（总结 / 必读 / 议程）
2. **怕什么**（风险 / 核实 / 伪信号）
3. **意味着什么**（机会 / 结构对照 / 跟踪清单）

只跑第 1 类 = 高效摘要；第 2+3 类才是爬虫覆盖面带来的超额价值。

### 2.2 一条配方只做一件事

反例：在「总结」里同时塞风险、机会、选题、人物追踪。  
正例：拆成独立菜单项，用户按场景组合。

### 2.3 强制可扫读 + 可追溯

每条结论尽量：

- 短句 / 短列表
- 附 1～3 条**依据标题**（可截断）
- 标置信度或信息充分度：`高 / 中 / 低` 或 `标题直接暗示 / 待核实`

### 2.4 强制承认无知

提示词中应明确要求：

- 标题未体现 → 写「标题未体现 / 信息不足」
- 禁止编造未出现的数据、引语、因果、内幕
- 禁止荐股、买卖点、政治站队、阴谋论

### 2.5 覆盖面优势怎么用

FeedGen 可聚合全球多源。配方应刻意利用：

- **同题多源**（对照、叙事分裂）
- **非英语世界 / 非头条地区**（被忽视的外溢）
- **高频公司/人物/机构点名**（追踪板）
- **旧闻翻炒与标题党**（降噪）

## 3. 推荐日常组合

### 3.1 固定「5 + 3」

**每天必跑（5）**

1. 30 分钟简报  
2. 风险雷达（总）或拆成「金融 / 地缘」  
3. 今日必读 10 条  
4. 需要核实优先  
5. 本周跟踪清单  

**按场景加跑（3）**

| 场景 | 加跑 |
|---|---|
| 投资 / 产业研究 | 技术范式迁移 + 资本流向暗示 + 行业垂直透镜 |
| 舆情 / 媒体 | 多源同题对照 + 叙事分裂图 + 情绪温度计 |
| 政策研究 | 政策红利窗口 + 监管与合规风暴 + 关键机构动作 |
| 个人晨报 / 内容 | 30 分钟简报 + 给我写选题 + 会议开场白 |

### 3.2 性价比最高的首批 8 条

若菜单不宜过长，优先启用：

1. 30 分钟简报  
2. 今日必读 10 条  
3. 金融系统性风险  
4. 地缘与供应链冲击  
5. 技术范式迁移  
6. 多源同题对照  
7. 需要核实优先  
8. 给我写选题  

内置「简报总结 / 风险挖掘」可与上表并存；也可把内置改名/改提示词后「恢复默认」。

## 5. 提示词写作规范

### 5.1 System 提示词应包含

1. **角色**：编辑 / 风险分析师 / 产业研究员…（与任务匹配）  
2. **信息边界**：只有标题（及可选摘要/来源），没有正文  
3. **禁止项**：编造、荐股、阴谋论、站队、恐慌措辞  
4. **语言与格式**：简体中文；可用小标题与列表；禁止 Markdown 代码块（与现有内置一致，便于 overlay 渲染）  
5. **不确定性话术**：可能 / 待核实 / 信号偏弱 / 标题未体现  

### 5.2 User 模板建议骨架

```text
【任务：{配方名}】
{一句话任务}

【分析/写作目标】
1. …
2. …

【硬性约束】
- 不编造…
- 每条结论尽量附依据标题
- …

【输出结构（严格按此顺序）】
## …
## …

【上下文】
页面范围：{{scope_label}}
标题条数：{{title_count}}
日期：{{today}}

【标题列表】
{{titles_block}}
```

### 5.3 温度与长度（经验）

| 类型 | 建议 |
|---|---|
| 简报 / 必读 / 工作流 | 克制、短、可扫读；400～900 字量级 |
| 风险 / 对照 / 因果 | 稍细，强调置信度与依据；避免长文 |
| 选题 / 口播 | 可稍活泼，但仍禁止编造事实 |

运行参数目前由服务端统一（DeepSeek）；配方侧主要通过提示词控制风格与篇幅。

### 6.1 30 分钟简报

**context_fields**：`title`

**system_prompt**

```text
你是高管简报写作者。只基于用户提供的标题列表工作，没有正文。
禁止编造未出现的事实、数据、引语或因果；信息不足处标明「标题未体现」。
语言：简体中文。客观、短句、高信息密度。
禁止输出 Markdown 代码块；可用小标题与短列表。
不要给出投资建议或政治站队。
```

**user_prompt_template**

```text
【任务：30 分钟简报】
请把下列标题整理成一份可在 3～5 分钟读完的高管简报。

【写作目标】
1. 用 2～3 句说明「今天这批标题整体在讲什么」。
2. 给出最多 3 条主线（每条 1～2 句 + 1～2 条依据标题）。
3. 给出最多 3 个「今日行动/关注项」（继续观察 / 优先核实 / 纳入跟踪）。
4. 给出「可稍后读」的次要主题（合并叙述，勿逐条复读标题）。

【硬性约束】
- 总篇幅约 350～700 汉字。
- 不要空泛宏观套话。
- 每条主线必须能从标题合理推断。

【输出结构（严格按此顺序）】
## 一句话总览
## 三条主线
## 今日行动项
## 可稍后读

【上下文】
页面范围：{{scope_label}}
标题条数：{{title_count}}
日期：{{today}}

【标题列表】
{{titles_block}}
```

### 6.2 今日必读 10 条

**context_fields**：`title`

**system_prompt**

```text
你是新闻策展编辑，擅长从大量标题中挑出「最值得点开」的条目。
只有标题、没有正文；排序依据只能是标题所暗示的影响面、新奇度、不确定度与冲突性。
禁止编造细节；禁止荐股与政治站队。
语言：简体中文。禁止 Markdown 代码块。
```

**user_prompt_template**

```text
【任务：今日必读 10 条】
从下列标题中选出最多 10 条最值得优先阅读的条目（可少于 10）。

【筛选标准】
- 影响面大、或不确定度高、或明显冲突/转折

- 营销味、旧闻翻炒、纯情绪标题降权

【每条必须包含】
- 标题原文（可轻微截断）
- 一句话理由
- 建议动作：点开核实 / 纳入跟踪 / 仅知晓

【输出结构】
## 必读清单
## 落选但可关注（最多 5）
## 策展说明（2～4 句）

【上下文】
页面范围：{{scope_label}}
标题条数：{{title_count}}
日期：{{today}}

【标题列表】
{{titles_block}}
```

### 6.3 需要核实优先

**context_fields**：`title` + `summary` + `source`

**system_prompt**

```text
你是事实核查预备编辑。任务不是下定论，而是找出「最需要进一步核实」的标题。
依据只有标题/摘要/来源；禁止补造事实。
重点：单源爆料、传闻措辞、数据缺出处、极端结论、互相矛盾。
语言：简体中文。禁止 Markdown 代码块。
```

**user_prompt_template**

```text
【任务：需要核实优先】
列出最需要核实的线索（5～12 条，可更少）。

【每条包含】
- 线索简述
- 风险类型：传闻 / 单源 / 数据含糊 / 因果过强 / 标题党夸张 / 相互矛盾
- 缺什么信息才能核实
- 依据标题（1～3 条）
- 优先级：高 / 中 / 低

【输出结构】
## 高优先级核实
## 中低优先级
## 暂可忽略的噪声
```

## 7. 菜单信息架构建议

避免一次启用 40+ 条导致选择瘫痪。

### 7.1 分层启用

| 层级 | 数量 | 内容 |
|---|---|---|
| 置顶常用 | 5～8 | 简报、必读、风险、核实、选题等 |
| 场景包 | 按需 | 投资包 / 舆情包 / 政策包（用启用开关管理） |
| 实验区 | 少量 | 新提示词试验，验证后再升为常用 |

### 7.2 命名规范

- 菜单名：**结果导向**（「今日必读 10 条」优于「分析一下」）  
- 说明：一句话写清读者获得什么  
- 内置与自定义：内置可恢复默认；实验用自定义，避免改坏内置后找不到原稿（可先复制文案到文档）

### 7.3 与主题筛选联动

推荐工作流：

1. 侧栏点某个**主题**或 Feed，缩小列表  
2. 再跑对应垂直配方 / 风险配方  
3. 全库「今天」范围则跑简报 + 议程 + 必读  

配方本身不扫全文、不另开爬虫；**列表越聚焦，配方越深。**

## 8. 评估与迭代

### 8.1 一条配方好不好的标准

- 30 秒内能否抓住重点？  
- 结论是否都能回到依据标题？  
- 是否经常幻觉补细节？（是则加强约束、减少摘要噪声）  
- 是否与其它配方产出高度重复？（是则合并或停用）  

### 8.2 迭代方法

1. 先改 **输出结构**（比改文风更有效）  
2. 再改 **硬性约束**（反幻觉、篇幅）  
3. 最后改角色语气  
4. 内置配方改乱了用「恢复默认」  

本轮不做「从当前结果反推提示词」；以「改提示词 → 立刻重跑」为主。

## 9. 反模式（尽量避免）

| 反模式 | 问题 | 改进 |
|---|---|---|
| 万能总结一条走天下 | 只有摘要价值 | 拆成正交透镜 |
| 要求「全面深度研报」 | 标题不够支撑，幻觉暴涨 | 限制篇幅 + 强制信息不足 |
| 暗示买卖点 | 合规与误导风险 | 只做主题/行业映射 |
| 菜单 30+ 全开 | 选择成本高 | 5+3 组合 + 场景包 |
| 所有配方都开 summary | 噪声与成本上升 | 按需勾选 |
| 输出长文无结构 | 难扫读 | 固定 `##` 小标题 |

## 11. 结果缓存与时间戳版本历史

每次成功运行配方会写入 `user_insight_recipe_runs`，便于同一阅读范围内**秒开**，并保留同日多次运行的细微差异。

### 11.1 缓存键

`user_id + recipe_id + scope_key + run_day`

| 字段 | 含义 |
|---|---|
| `scope_key` | 前端根据当前阅读范围构造，如 `day:today`、`feed:123`、`tag:45`、`article:789` |
| `run_day` | 用户本地自然日 `YYYY-MM-DD` |
| `title_count` / `input_fingerprint` | 仅元信息；**不参与**是否秒开 |

### 11.2 交互

1. 点击配方 → 先 `GET /api/ai/recipes/:id/runs/latest`  
2. 有缓存 → 立即展示（meta 标「缓存」）  
3. 无缓存 → `POST .../run` 调 AI，落库后展示（「刚生成」）  
4. 结果弹层可切换同日历史版本（时间戳 + 条数）  
5. **重新生成** → `force_refresh`，追加新版本，不覆盖旧版  
6. AI 菜单顶部 **「今日报告」** → 报告台：左配方列表 / 右正文，一次浏览当前范围+日期下全部已生成结果  

### 11.3 保留策略

- 同一用户 / 配方 / scope / 自然日最多 **20** 条  
- 写入时顺带清理超过 **30** 天的旧 run  

### 11.4 相关 API

- `GET /api/ai/runs/digest?scope_key=&run_day=`（报告台一览）
- `GET /api/ai/recipes/:id/runs/latest?scope_key=&run_day=`
- `GET /api/ai/recipes/:id/runs?scope_key=&run_day=&limit=`
- `GET /api/ai/recipes/runs/:runId`
- `POST /api/ai/recipes/:id/run`（body 可含 `scope_key`、`run_day`、`force_refresh`）

## 12. 与系统能力的边界

| 能做 | 暂不在配方内做 |
|---|---|
| 当前列表标题/摘要/来源的多透镜分析 | Agent 多步工具、自动联网 |
| 用户自定义提示词与启用排序 | 配方市场 / 跨用户分享 |
| 内置总结/挖掘的覆盖与恢复默认 | 对单篇正文做超长精读（成本高） |
| 与主题/Feed/今天等范围筛选配合 | 自动每天定时跑全部配方（可后续产品化） |
| 同范围同日结果秒开与版本历史 | 按标题指纹强制命中缓存 |
